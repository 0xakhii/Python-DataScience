Exercise 00 — statistics: Variadic Arguments & Descriptive Statistics

Files: statistics.py | tester.py

Concepts Explained

Variadic Parameters (*args and **kwargs)

*args packs any number of positional arguments into a tuple ((1, 42, 360, 11, 64)).
**kwargs packs any number of keyword arguments into a dict ({'toto': 'mean', 'tutu': 'median', 'tata': 'quartile'}), preserving insertion order (Python 3.7+).
In ft_statistics, the keyword names (toto, hello, world) are arbitrary; only the keyword values (kwargs.values()) determine which statistics to print. Unknown values (like "heheh") are silently ignored.

Numeric Validation & The bool-is-an-int Pitfall

In Python, bool is a subclass of int, so isinstance(True, int) evaluates to True!
Line 52 explicitly checks isinstance(x, (int, float)) and not isinstance(x, bool) so booleans are rejected instead of being silently treated as 1 and 0.

Exercise 01 — in_out: Closures & nonlocal

Files: in_out.py | tester.py

Concepts Explained

First-Class & Higher-Order Functions

In Python, functions are objects just like numbers or lists: they can be passed as arguments (outer(3, square)) and returned from other functions (return inner).
A function that takes or returns another function is called a higher-order function.

Lexical Scope (LEGB Rule) & Closures Python resolves variable names in four ordered scopes: Local 
→
→ Enclosing 
→
→ Global 
→
→ Built-in.

When outer returns inner, outer's stack frame finishes, yet inner keeps references to the enclosing variables x, count, and function inside cell objects (inner.__closure__).
Every call to outer(...) creates a brand-new set of closure cells, so my_counter = outer(3, square) and another_counter = outer(1.5, pow) keep completely independent state without using any global variables.

Why nonlocal Is Required

Inside inner(), reading an enclosing variable works automatically, but assigning to it (count += 1, x = function(x)) makes Python treat count and x as new local variables—causing an UnboundLocalError!
Declaring nonlocal count, x tells Python to rebind the existing variables in the nearest enclosing function scope (outer) rather than creating local shadows or touching module globals.

Exercise 02 — callLimit: Decorator Factories & Wrappers

Files: callLimit.py | tester.py

Concepts Explained
Decorators vs. Decorator Factories (3 Nested Layers) A plain decorator (@dec) takes a function and returns a replacement function (2 layers). Because @callLimit(3) accepts a parameter (limit = 3), it requires 3 nested functions:

Syntactically, writing:

python
@callLimit(3)
def f():
    print("f()")

is 100% equivalent to:

python
def f():
    print("f()")
f = callLimit(3)(f)

Transparent Argument & Return Forwarding (*args, **kwds)

Defining limit_function with (*args: Any, **kwds: Any) allows @callLimit(...) to wrap any function regardless of its signature (zero arguments like f(), or positional/keyword arguments like add(10, b=5)).
Returning function(*args, **kwds) preserves the wrapped function's return value when allowed, and returns None when blocked.

Closure Isolation Across Decorated Functions

Each @callLimit(...) decoration invokes callLimit separately, allocating its own count = 0 closure cell. Thus f (limit 3) and g (limit 1) track their call counts independently.
Functions Breakdown
In callLimit.py
callLimit(limit: int) Outer decorator factory; stores limit and initializes count = 0, returning callLimiter.
callLimiter(function) The actual decorator receiving the target function function, returning the wrapper limit_function.
limit_function(*args: Any, **kwds: Any) Checks if count < limit: using nonlocal count. If under the limit, increments count and returns function(*args, **kwds). Otherwise prints f"Error: {function} call too many times" (where {function} formats as <function g at 0x...>) and returns None.
Exercise 03 — new_student: Dataclasses, field(), & __post_init__

Files: new_student.py | tester.py

Concepts Explained

What @dataclass Generates Automatically Decorating Student with @dataclass inspects its type-annotated class attributes and synthesizes boilerplate special methods automatically:

__init__(self, name: str, surname: str, active: bool = True) (only including fields with init=True)
__repr__(self) displaying every field with repr=True (the default) in declaration order: Student(name='Edward', surname='agle', active=True, login='Eagle', id='...')
__eq__(self, other) for field-by-field structural equality comparison.
Because __repr__ is generated automatically, Student satisfies the constraint "You must not use __str__, __repr__ in your class."

Controlling Fields with dataclasses.field()

active: bool = field(default=True): Included in __init__ with default True, so callers may omit it or override it (active=False).
login: str = field(init=False): Excluded from __init__ parameters—passing login=... raises TypeError: Student.__init__() got an unexpected keyword argument 'login'. Still included in __repr__!
id: str = field(init=False, default_factory=generate_id): Excluded from __init__, and calls generate_id() fresh for every new instance.

IMPORTANT

default_factory=generate_id vs default=generate_id(): If you wrote default=generate_id() (with parentheses), Python would call generate_id() once when the class is defined, giving every Student instance the exact same ID! Passing the function reference to default_factory=generate_id invokes it dynamically on every instantiation so each student gets a unique random ID.

The __post_init__ Lifecycle Hook login depends on self.name and self.surname, so it cannot be computed via a 0-argument default_factory. Instead, @dataclass's generated __init__ automatically calls __post_init__ right after assigning all initialized fields:
